# 工作流：从剧本到两份交付物

管线：`剧本 + 配音 + 参考图` → `生成单元` → `镜头` → `分镜表` + `prompt 清单`

---

## 0. 覆盖率校验（**比格式校验重要得多，每次交卷前必做**）

**分镜表格式再漂亮，漏了剧情就是废的。** 这一步必须在交付前做，而且要真的做，不能凭印象。

**做法**：拿剧本原文和分镜表逐条比对——

1. 把剧本里**每一句台词**（含 OS / 画外音）列出来
2. 把分镜表里**每一镜的「台词」列**按顺序拼成一条文本
3. 逐条检查：每句台词是否都能在分镜里找到对应位置
4. **动作行（`△` 开头的行）也要过一遍**——有没有哪一整段动作被丢掉

**比对时只取引号内的对白内容**，剥掉角色名和时长标注。否则长台词被拆成两镜时，中间的标注会打断连续性，产生假阳性。

### 剧情为什么会漏（真实原因，不是手滑）

最常见的原因是**中途改了单元结构**：

> 最初把某场戏规划成 4 个生成单元 → 定稿时为了控制时长压成 3 个 → **第 4 个单元的内容没有并回前 3 个，直接丢了**。

这种删减**不会产生任何报错**：时间轴照样连续、素材绑定照样完整、每镜照样有备注。**格式校验会 100% 通过，而内容是残缺的。**

**所以：只要动过单元数量或拆分方式，必须重跑一遍覆盖率校验。** 单元数变了 = 内容重新分配过 = 必须重查。

### 落地方式

- **有脚本就用脚本**：输入 = 剧本文本 + 分镜表的「台词」列，做顺序匹配。写一次能复用到整部剧
- **没脚本就手工逐条打勾**：把剧本台词复制成一份清单，在分镜表里逐条划掉。**不要跳，也不要凭印象**
- 覆盖率校验和格式校验是**两道独立的门**，都要过。格式校验全绿不代表内容完整

### ⚠️ 校验器本身也会静默失效——必须验证校验器

**这是本项目真实踩过的坑**：检查器原本用整数正则匹配时间轴（`^(\d+)-(\d+)s$`）。后来时长改成带小数的写法（`1.5-4.5s`），正则一条也匹配不上 → **被检查的时间轴数量变成 0** → 所有时长校验静默跳过 → 检查器依然打印「问题汇总：无，全部通过」。

**一个检查 0 个对象的校验器，看起来和检查了 68 个对象、全部合格的校验器一模一样。**

**所以校验器必须自证在工作**：

1. **输出「被检查了多少项」**，不要只输出「通过」。正确形态：
   ```
   E01: 剧本台词 19 条 / 动作 16 行 → ✅ 全覆盖
   合计漏掉 0 条台词
   ```
   而不是：`校验通过 ✓`

2. **看到总数为 0、或明显偏小，就是校验器坏了**，不是数据干净。0 是一个危险数字。

3. **改过数据结构或写法的，必须重跑一次校验器并检查计数**。新增小数、新增列、改时间轴格式，都可能让正则悄悄失效。

4. **别把「校验通过」当成可以交付的信号。** 它是两道门之一，而且只有当它报出了合理的计数时才算数。

## A. 开工前：把手上的东西点清

**先分清"项目级"和"每集级"两步。**

### A1. 项目首次开工（只做一次）

1. **剧本**：通读，标出集数、场次边界、台词归属。
2. **类型**：短剧 / 电影 / 动漫（动漫再确认 **2D / 3D / 三渲二**）。没问过就先问。
3. **字幕路线**：后期添加 / 让模型生成。问一次，项目级固定。
4. **建全剧资产表**：人物 / 场景 / 站位 / 配音 / 道具 + 命名规范（`assets/project-assets-template.md`）。
   - **形状先定死**：**每个角色 / 场景 / 道具各起一个 `###` 标题**，字段列在下面。**不要用大宽表把多项挤成一行**——markdown 表格装不下多行代码围栏，一用表，出图提示词就只能被挪到别处，那就破坏了"一个条目一个地方"。详见模板顶部的「结构铁律」。
   - 人物分两层：主角与主要配角写**完整表演档案**，功能性配角写**三行精简档案**（也是**一人一条**，不是一张表）
   - 配音写**声线档案**——这是给录制与选声用的，**不进 prompt**
5. **出图**（默认做，**用户说"图我自己出"就跳过**）：
   - 按 `references/asset-pipeline.md` 写全剧参考图的出图提示词，**直接写在每个角色 / 场景 / 道具条目下面**——人物→`01-人物资产.md`、场景→`02-场景资产.md`、道具→`04-道具资产.md`。**不另建"全剧出图提示词"文件**：每个人的档案和他的提示词挨在一起，看一个角色不用翻两处。
   - **一图一参考**：要几个视角就出几张，**不要拼成一张**

### A2. 每集开工

1. **剧本**：读这一集的场次与台词。
2. **配音音频**：这一集有几段、每段多长、每段覆盖哪几句台词。**这是时长的唯一权威来源。**
3. **参考图**：从资产表里取这一集要用的人物图、场景图、站位图（编号沿用资产表，不要另起）。
4. **继承项目约定**：类型档、字幕路线、画幅、跨集连续性锁——**照抄，不要每集重新决定**。

### 拿不到配音时间码怎么办

理想情况是用户直接给你每句台词的时间码。如果拿不到，用**字数为基线估算**：

- 中文常态语速约 **4–5 字/秒**
- 快演（吵架、揭露身份）约 5–6 字/秒
- 慢演（威胁、告别）约 2–3 字/秒

这是**估算，不是事实**。所有估算出来的时长都要在分镜表里标 **`待核`**，并在交付时明确告诉用户"这些时长是按字数估的，请对着实际配音校对一遍"。

> 不要把这个估算值当成精确数据写进交付说明里当结论。它只是让流程能跑起来的脚手架。

## B. 切生成单元

一个**生成单元 = 一次 Seedance 生成任务**，上限 30 秒。切分按叙事/场景自然分段，**不硬凑**：

**遇到下面任何一条，就是单元边界：**

| 触发条件 | 说明 |
|---|---|
| 换场景 | 地点变了，环境参考图也要换 |
| 换情绪段落 | 情绪值跨度 ≥3 分（如从 3 分日常跳到 8 分打脸） |
| 换人物组合 | 出场人物集合变了，参考图要重新绑定 |
| 达到 30 秒 | 硬上限，必须断 |
| 换时间/时空 | 闪回、回忆、时间跳跃 |

**长度约束（只有三条硬约束）：**

- **单元总长 ≤30 秒**——硬上限
- **含 2 个以上镜头的单元，不要短于 10 秒**——官方明确说多镜低于 ~10s 会饿死节奏
- **单镜 ≥1 秒**——低于 1 秒模型会丢掉动作
- **只有 1 个镜头的单元**不受 10 秒下限约束，但同样不要低于 1 秒

**单元编号**：`U<两位集号>-<两位序号>`（如 `U07-03`）。**用集号前缀而不是全剧连续编号**——因为分镜常常是跳着做集的，连续编号在跳做时会失效，补做前面几集就得全部重编。集号前缀天然保证全剧唯一。如果你确定会严格按顺序做完整部，`U001` 起的连续编号也可以，二选一，但**整部只能用一种**。

## C. 单元内切镜

**一个镜头 = 一次切视角的时机。**

**什么时候该切：**

- 视线转移：一个人看向另一个人/物，就该切到被看的那一方
- 信息揭示：新信息露头（一封信、一个背影、一个身份）
- 情绪跳变：情绪值跨越 ≥2 分
- 说话人切换：换人说话，尤其配正反打
- 动作完成：一个主动作做完，需要开启下一个

**每个镜头必须满足：**

1. **一个主动作 + 一个运镜**。两个主动作塞一个镜头，模型会跳过或压缩其中一个。
2. **结束在一个完成的视觉状态**。下一镜要能从这个状态接上去——这是官方强调的端点纪律（endpoint discipline）。
3. **时长 = 这一镜在成片里应该占多久**（见下面「时长怎么定」）。不要垫时长。

**表演怎么落进镜头（写「画面内容」和「拍摄备注」时）：**

> 完整表演体系见 `shot-language.md` 第 13 节。**写镜头内容时至少要过一遍"五支柱"和"坏表演图鉴"。**

- **每个在场角色都要有目标**——`逼他认错`、`让他闭嘴`，**不能只是"在说话"**
- **写行为，不写情绪**：不写"她很生气"，写"她把杯子往桌上一顿，杯底磕在瓷面上"
- **每个内心状态都要有身体标记**；每个小动作都要带**触发条件**
- **眼神生命是硬要求**：视线不冻结、眼睛先于头转、catchlight 要活（§13.5）
- **反应用"从对方半句话时就开始"**写，不要等对方说完才反应
- **威胁不预热**：不要写"缓慢转头 + 眯眼"预告暴力
- 写完后对着 **§13.8 坏表演图鉴 15 条**扫一遍

> ⚠️ **"分拍"和"状态"的作用域**：prompt 文本里写**状态**（`已经挥到一半`）；**分拍（起手→命中→余势）只写在拍摄备注里**，不进 prompt。两者不冲突。

**时长怎么定（重要）：**

每镜时长不是"填满预算"，而是**这一镜在成片里应该占多久**：

| 镜头类型 | 怎么定 | 常见区间 |
|---|---|---|
| **台词镜** | 台词长度 + 0.5–1.0 秒缓冲 | 2–6.5 秒（**压不动**，长台词自然撑出长镜） |
| **动作镜**（耳光、砸击、摔、打斗、一个转身） | 按动作实际需要 | **1.5–3 秒** |
| **反应镜**（一个表情、一次回望、一次停顿） | 按表演实际需要 | **1.5–3 秒** |
| **情绪镜 / 收尾镜**（凝视、镜头拉高、画面变暗） | 给足呼吸 | 3–6.5 秒 |

官方说的"**≈4–6 秒一镜**"是**排片用的规划平均值，不是硬下限**。把它当硬下限，会得出"一记耳光也要 4 秒"这种荒谬结果。

**短镜必须写「动作余量」**：一个 1.5 秒的动作镜要写明**分几拍、每拍多久**，动作落在第几拍。例如耳光镜：

```
0–0.4s 起手甩出 → 0.4–0.8s 命中（血丝在此刻出现） → 0.8–1.5s 头被打偏的余势
```

如果写成"动作占满全镜"，动作会卡在第 0.1 秒，剪辑想裁短都没得裁。

**关于"短剧要快"的正确理解：**

短剧的"快"靠**单元内镜头多**，**也**靠**单个动作镜短**——但这两个受两头夹着：

- ✅ 20 秒放 6 个镜头，其中动作镜 1.5–2 秒、台词镜 4–5 秒 → 观感快，模型能执行
- ❌ 20 秒放 20 个 1 秒镜头 → 模型过度剪切、丢剧情，出来是一团糊

**判断标准是"这一镜有没有塞进超过它时长的内容"**，而不是"这一镜够不够 4 秒"。一段无台词的戏想更快，就**多切几刀**（同时守住单元 30 秒上限），而不是让每一刀都只剩 1 秒。

**情绪值 → 切镜速度映射**（情绪值 1–10，填进分镜表）：

| 情绪值 | 单镜时长 | 切法 |
|:---:|---|---|
| 1–3 低（日常、走路、铺垫） | 4–6s | 固定机位，静接静，让观众看清环境 |
| 4–7 中（争执、怀疑、谋划） | 台词镜 4–5s；动作/反应镜 2–3s | 正反打近景，轻微推拉 |
| 8–10 高（打脸、揭秘、下跪、死亡） | 台词镜 3–5s；**动作镜可到 1.5–2s** | 特写 + 急推，动接动，音效炸点 |

连续 3 个单元情绪值都在 9 分，观众会累。主动插一个 3 分的单元让节奏喘口气，后面那个 9 分才炸得起来。

## D. 从配音倒推时长

**顺序永远是：先定音频边界 → 再定镜头边界 → 最后定单元边界。**

1. 把配音按**气口**（停顿、换气的静默）切成小段
2. 每个小段归属到它所在的镜头——**台词落在说话人出镜的那个镜头里**
3. 镜头时长 ≈ 该镜内所有台词时长 + 前后留白（通常各 0.3–0.5s）
4. 如果一段台词算出来明显超过 6.5 秒（约 40 字以上）：**拆成两个镜头**。两种拆法——① 同一说话人跨两镜（**中间不能有呼吸断点，两镜人物位置与光向必须一致**）；② 切一个反应镜（对方的表情、手部、道具）承接后半句
5. 如果算出来不足 1.5 秒：和相邻镜头合并，或者这个镜头的画面里补一个动作/运镜把时长撑起来

**对不上就是信号**：如果某个单元怎么排都超过 30 秒，说明这个单元该拆成两个；如果某个单元只有 6 秒却塞了 4 个镜头，说明剧本信息密度和时长不匹配——**报告给用户**，不要自己删戏。

## E. 分镜表填写规范

落地成 `<集号>-分镜表.md`，结构用 `assets/storyboard-template.md`。

**列的含义与填法：**

| 列 | 填什么 | 注意 |
|---|---|---|
| 单元 | `U01` | 全剧连续编号 |
| 镜号 | `U01-S1` | 单元内连续 |
| 时间轴 | `0-4s` | **单元内相对时间**，从 0 开始，段与段必须连续无缝 |
| 时长 | `4.0` | 秒，一位小数。**总和必须等于单元实际生成时长** |
| 景别 | 近景 / 特写 / 中景… | 用 `shot-language.md` 的词 |
| 运镜·机位 | 固定 / 急推 / 低角度仰拍… | 一镜只写一个主运镜 |
| 画面内容 | 谁在哪、在做什么 | 写成 prompt 能直接用的描述 |
| 台词 | `角色："台词"（3.2s）` | 标明说话人；静默镜写 `—` |
| 音效 | 环境音 / 动作音 / 无 | 用于写进 prompt 的声音指代 |
| 参考素材 | `图1,图3,音频1` | 只写这个镜头真正用到的 |
| 衔接 | 硬切 / 动作匹配 / 闪白… | 说明与下一镜怎么接 |
| 情绪值 | `1-10` | 用来对齐切镜速度 |
| 拍摄备注 | 见下 | **每镜必填，不许留空** |

**单元汇总行**：每个单元开头写一行 `单元 U01｜0:00–0:18｜4 镜｜参考：图1,图2,图3,音频1`。这行就是 prompt 的素材指代来源。

### 「拍摄备注」列（每镜必填）

这一列装的是**不进生成提示词、但对成片有影响**的执行提示。写它的意义是：**生成的时候不用动脑子，剪辑的时候照着做。**

用图标标类别，方便筛选：

| 标记 | 类别 | 写什么 |
|:---:|---|---|
| ⚠️ | **生成风险** | 这一镜最容易崩的地方，**并给一个备选拍法** |
| 🔒 | **连续性锁** | 跨镜、跨集不能变的东西（血迹位置、道具归属、服装） |
| 📌 | **后期处理** | 后期要贴的字、要对位的音效、要加的层 |
| 📐 | **UI 安全区** | 竖屏顶部 20% / 底部 15% 的构图约束 |
| 🎭 | **表演要点** | 关键表演提示、速度指令、"不要演成什么" |

**为什么必须每镜都写、不许留空**：备注的价值恰恰在于"生成时不用现想"。留空一镜，就意味着生成到那一镜时要临时判断——而临时判断正是错误发生的地方。常规镜头（定场、正反打）哪怕只写一句连续性锁，也比空着强。

**四种几乎每集都会用到的备注**：

1. **字幕归后期** —— 剧本里的 `【字幕：…】`、手机短信、名片地址、屏幕信息，全部写进备注交给后期，**提示词里一个画面文字都不出现**（配合 `references/sd25-contract.md` 负向控制一节的写法）
2. **借位替身** —— 打斗、掌掴、砸击类镜头，写明"用借位/掠过，不拍实打接触"，冲击感靠镜头晃动 + 后期音效
3. **情绪峰值标记** —— 该镜是全集峰值时写明情绪值，并提示"这里的慢是刻意的，不要剪短"
4. **收尾镜构图** —— 拉高/俯视类收尾镜，写明人物避开 UI 遮挡区

## F. 选骨架（写 prompt 之前先定这个）

一个单元只能有**一种**结构。混用两套骨架是模型混乱的常见原因。

| 骨架 | 长什么样 | 什么时候用 |
|---|---|---|
| **① 镜头序列骨架**（默认） | `0-4s 镜头1（近景，固定机位）：……` 逐段写切镜 | 单元里有**明确的切镜**。短剧绝大多数情况用这个 |
| **② 阶段骨架** | `[阶段1 \| 0-10秒] 初始状态：…… 主要事件：…… 结束状态：……` | 一段**连续的大动作**、长镜头、或你只想给"时间预算"而不想指定剪辑点 |
| **③ 一镜到底** | 明确写 `一镜到底，中途不切` + 用 `起 / 然后 / 最后` 描述阶段 | 一段完全不断的连续镜头 |

**判定方法**：问自己"这一段里我要不要切视角？"——要切就用 ①；不要切、但动作分几个阶段，用 ②；完全不切且只有一个连续运动，用 ③。

**为什么阶段骨架值得单独备一套**：官方伙伴向导把**阶段当默认**、把精确时间戳当"点强化"。原因是长段落里，写死每一个剪辑点反而会误导模型——它做不到帧级精确，强行指定边界会让动作被切碎。所以当一段戏是"连续推进的一件事"，用阶段骨架更稳。

### 阶段骨架的写法

```
[生成目标] 生成一段 <类型>。核心主体是 <主体>，主要事件是 <故事概述>。
[阶段1 | 0-10秒] 初始状态：<人物、道具、场景的初始状态>。
                主要事件：<一个主动作>。结束状态：<人物位置、道具归属、画面里可见的状态>。
[阶段2 | 10-20秒] 承接上一阶段：<必须保持不变的状态>。
                主要事件：<……>。结束状态：<……>。
[阶段3 | 20-30秒] 主要事件：<收尾事件>。结束状态：<最终可见状态>。
[保持一致] 保持 <角色身份、角色数量、服装、道具归属、空间方向、音频关系> 一致。
```

**每个阶段只给一个主要状态变化 + 一个可见的结束状态。** 两个变化塞一个阶段，模型会跳过其中一个。

### 场景块（多个场景时可以替代逐场描述）

如果一次生成里要跨好几个场景，用场景块代替逐段描述：

```
场景 N | <场景名>
使用：本场需要的人物、道具、场景、运动参考
事件：一个主动作
结束状态：位置、归属、以及结束时画面里还留着什么
```

多素材生成的目的是**帮模型挑对当前场景要用的素材**，不是让所有素材同时出现。

**软边界提醒**：无论用哪种骨架，时间区间都是**预算而不是剪辑点**——动作落在边界前后一点是正常的，永远不会帧级精确。

## G. prompt 组装

一个单元一条 prompt，写进 `<集号>-prompts.txt`。用七段结构（模板见 `assets/prompts-template.txt`）：

1. **【素材指代】** —— 按上传顺序写清每个图和音频的用途。`图1=人物A（林晚）形象参考；图2=场景（别墅客厅）参考；音频1=人物A 的台词`
2. **【一句话概述】** —— 主体 + 地点 + 事件 + 题材风格 + 画幅
3. **【主体设定】** —— 每个主体一段：参考哪张图、长相、年龄、服装、气质。**不要复述图片本身已经很精确的信息**，只写"参考图几"即可
4. **【环境】** —— 参考哪张场景图 + 这一场戏特有的氛围
5. **【整体风格】** —— 光影、质感、色调 + **画幅写死**（`9:16 竖屏` 或 `16:9 横屏`）
6. **【分镜头】** —— 按时间轴逐段：`0-4s 镜头1：景别+机位+画面+动作；台词（角色）"……"`。段与段连续，每段只给一个主动作 + 一个运镜
7. **【整体要求】+ 负向控制** —— 贯穿全片的细节（机位、环境、声音、氛围）+ `不额外加入对白字幕`、`无bgm，只生成环境音和动作音`

**逐段写完回头检查一件事**：每一段的文字量是否大致均衡。官方明确说**内容太少模型自由发挥、内容太多过度剪切**。

- [ ] **每一镜都有拍摄备注，没有留空**（生成风险 / 连续性锁 / 后期处理 / UI 安全区 / 表演要点）

## I. 遇到冲突怎么处理

| 情况 | 处理 |
|---|---|
| 剧本一场戏远超 30 秒 | 拆成多个单元，报告拆分点给用户确认 |
| 某单元塞不进 30 秒 | 拆单元，不要把动作镜压到 1 秒以下，也不要让台词镜短于台词本身 |
| 剧本要求单镜超过 8 秒 | 拆成两镜，或用"一镜到底"写法（写 `single continuous take`，并取消硬切标注），但要提醒用户 2.5 长镜稳定性会下降 |
| 一集人物超过 8 个 | 按单元拆分素材，每个单元只传这一场需要的人 |
| 用户没给参考图 | **停下来问**。不要用纯文本编人物长相——那样跨镜一致性必然崩 |
