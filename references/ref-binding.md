# 参考素材绑定规程

用户给的是四类素材：**人物图、场景图、站位图、配音音频**。本文件规定它们怎么编号、怎么分组、怎么在 prompt 里指认、怎么不出错。

---

## 1. 编号规则：按上传顺序，唯一编号

**编号 = 上传顺序**，这是官方的对应方式，不能自己另起一套。

- 图片：`图1`、`图2`、`图3`……（界面上也常显示成 `@Image 1`）
- 视频：`视频1`、`视频2`……
- 音频：`音频1`、`音频2`……

**用界面实际显示的那种写法**。你的界面上是 `@Image 1` 就写 `@Image 1`，是 `图1` 就写 `图1`——**不要自创、归一化或重排**已给的标记。

所以每个生成单元在 prompt 清单里必须先给一份**上传顺序清单**，用户照着这个顺序传：

```
上传顺序：1)=人物A定妆图  2)=人物B定妆图  3)=别墅客厅场景图  4)=两人对峙站位图  5)=音频A1
对应编号：  图1            图2            图3              图4              音频1
```

**顺序写错 = 全员串脸。** 这是最容易犯也最致命的错误。

---

## 2. 一个素材只给一个主角色

每个参考素材只承担**一个主要角色**。角色混在一起，人物身份、运动、运镜、环境会互相渗透，最后谁都像谁。

| 素材 | 主角色 | prompt 里的写法 |
|---|---|---|
| 人物定妆图 | **形象** | `图1 是林晚的形象参考` |
| 多人物构图 / 站位图 | **站位** | `图4 是两人对峙的站位参考` |
| 场景图 | **环境** | `图3 是别墅客厅的环境参考` |
| 风格图 | **风格** | `图5 是画面风格参考` |
| 视频 | **运动 / 运镜** | `视频1 的动作与运镜参考，顺序保持一致` |
| 音频 | **台词 / 音色** | `音频1 是林晚的台词，对应图1` |

---

## 3. 分组写法（素材一多就必须用）

素材少的时候，平铺一张清单还看得清。素材一多，扁平的清单会糊在一起。**把所有参考分进四个带标签的组，每组带自己的规则**：

```
[角色]
<林晚> 对应 图1。只取外观、发型、服装。
<周砚> 对应 图2。只取外观、发型、服装。
<周母> 对应 图3。只取外观、发型、服装。
四个角色的外观、服装、动作、站位和对白不得互换。

[道具]
<婚戒> 对应 图4，只属于 <林晚>。
<酒杯> 对应 图5，只属于 <周砚>。

[场景]
<别墅客厅> 参考 图6。只取空间、材质与光线，不要参考图中的人物。

[运动与音频]
视频1 定义 <林晚> 摔手机的动作。不要使用视频中的人物与场景。
音频1 定义 <林晚> 的声音与指定台词。
```

| 组 | 这一组的规则 |
|---|---|
| **`[角色]`** | 每张图给外观、发型、服装，**并加一条禁止互换的规则** |
| **`[道具]`** | 每个道具**只属于一个所有者**，归属关系写在组里 |
| **`[场景]`** | 只取空间、材质、光线——**绝不取图中的人物** |
| **`[运动与音频]`** | 视频**只定义运动**；音频**只定义声音与台词**——不是人物，也不是场景 |

**音频尤其要写清楚**：音频定义的是"声音和对白"，**不是"人"**。不写，模型会以为音频里能提取出人物形象。

---

## 4. 一行一个主体，一行一个参考

**每个需要参考的主体单独一行，每行只绑一个参考。** 这是官方伙伴向导里"DO NOT WRITE"表里点名反对的写法：

| ✅ 这样写 | ❌ 不要这样写 |
|---|---|
| `<林晚> 对应 图1。只取外观、发型、服装。`<br>`<周砚> 对应 图2。只取外观、发型、服装。` | `"图1到图4分别是四个角色。"` |

合并成一句会让模型把四个角色混在一起。**逐行写，逐行绑。**

同时说明**从参考里取什么**：

- 角色 → 外观、发型、服装
- 道具 → 结构、材质、颜色
- 场景 → 布局、建筑、光线

---

## 5. 转移与忽略条款（防止角色互相污染）

每个绑定了角色的参考，最好补一句"只控制什么、不参考什么"：

```
图1 只控制林晚的形象；不参考该图的背景与光线。
图4 只控制两人站位；不参考该图的人物长相与服装。
音频1 只控制林晚的台词与音色；不参考其音乐性。
```

R2V 最容易翻车的地方就是：**身份、运动、运镜、环境、音频这五个角色互相串**。

---

## 6. 同一角色的多个视角（2.5 独有）

2.5 是唯一支持**直接从 prompt 把多个视角融合成一个锁定身份**的版本。要**逐个视角显式声明**，最后用一句收口：

```
图1 定义 <林晚> 的正面视图。
图2 定义 <林晚> 的背面视图。
图3 定义 <林晚> 的面部细节，中性表情。
图4 定义 <林晚> 的面部动态与牙齿，强烈情绪。
以上四张图定义同一个 <林晚>。整段输出中只能出现这一个这样的人。
```

**机位预算**：**每一个角度都要占用 30 个图片名额里的一个。**

- **超过 5 个角色，改用"角色设定图 + 主体档案"来锁定身份**（见下一节），不要再一人多视角
- **绝对不要把多个视角合成一张拼图**——必须拆成独立图片分别传

**拍摄多视角素材时的三条实用建议**（写进给用户的说明里）：

1. 在**中性浅灰背景**上生成每个视角
2. **务必包含一帧强烈表情**（比如发怒或大笑），让模型学到面部动态与牙齿结构，而不只是静止的脸
3. 超过 5 个主体时改用**单视图**更稳

---

## 7. 主体档案块（角色跨场次反复出现时用）

同一个角色要在多个场景里反复出现、每次用不同参考时，给它建一个**主体档案**——把关于这个角色的一切收在一个块里。**这和 `assets/project-assets-template.md` 的全剧资产总表是配套的**：资产总表是人看的登记，主体档案是塞进 prompt 的版本。

```
[主体档案：林晚] 外观与服装：图1。固定道具：<婚戒> 来自 图4。
活动场景：<别墅客厅>、<门外台阶>。
运动参考：视频1 的摔手机动作。
不要使用：其他角色的服装。不要给这个角色 <周砚> 的酒杯。
```

---

## 8. 连续性来源 vs 运动参考

- **标准形象参考**控制不可变的身份
- **上一段的成品或末帧**控制临时的开场状态
- **运动参考**只能在明确允许时控制运动或运镜

**绝不能让运动参考覆盖掉人物身份、服装、产品几何形状。** 一句话：身份归身份图管，运动归运动素材管。

---

## 9. 素材数量控制

| 项目 | 建议 |
|---|---|
| 单个单元的画面主体 | **1–8 个**较好，9–12 个可试但稳定性下降 |
| 超过 5 个主体 | 用**单视图**更稳；要多视角就拆成多张图分别传 |
| 带音频的主体 | 音视频建议 **5–10 秒**，更长会掉稳定性 |
| 一集人物很多 | **按单元拆素材**：这个单元只传这一场戏需要的那几个人 |
| 精准补拍的 6–8 张图 | 可试，但稳定性下降，可能需要抽卡 |

**核心认知**：**参考素材加得多，不等于控制力更强。** 素材多了一样会互相干扰。多素材生成的目标是**帮模型挑对当前这一场要用的素材**，不是让所有素材同时出现。

---

## 10. 每个单元的素材清单（分镜表里要有）

每个生成单元开头写一行，直接对应上传顺序：

```
单元 U01｜0:00–0:18｜4 镜
上传顺序：1)图-林晚定妆 2)图-周砚定妆 3)图-客厅场景 4)图-两人站位 5)音频-林晚A1
素材绑定：图1=林晚形象；图2=周砚形象；图3=客厅环境；图4=两人站位；音频1=林晚台词
```

这行就是 prompt 第一段【素材指代】的来源，不要凭记忆写。

---

## 11. 常见翻车与修法

| 症状 | 根因 | 修法 |
|---|---|---|
| 多人串脸、角色重复 | 靠图上的文字区分角色，或用了"图1到图4分别是四个角色"这种合并句 | 改成**一行一个主体**；把图上的字去掉 |
| 环境跟着人物图跑了 | 没写"只控制形象，不参考背景" | 补转移/忽略条款 |
| 人物长相在镜头间变了 | 多镜 prompt 里没有每个镜头都声明形象来源 | 每个镜头重复同一句形象声明 |
| 传了 10 个主体，一半不像 | 主体数超过稳定区间 | 按单元拆素材，每单元控制在 8 个以内 |
| 站位乱了、视线不搭 | 站位图没有绑定，或只绑了没写"不参考长相" | 绑定站位图并补忽略条款 |
| 台词和嘴对不上 | 音频没有绑到具体人物 | 写 `音频1 是林晚的台词，对应图1` |
| 模型试图从音频里提取人物 | 没说明音频只定义声音与台词 | 补 `音频1 只定义声音与台词，不定义人物与场景` |
| 多视角融合后还是像多个人 | 用了拼接图，或没有"以上N张图定义同一个人"的收口句 | 拆成独立图片，补收口句 |
