# Seedance 2.5 提示词硬规范

> 依据：火山方舟《Doubao Seedance 2.5 提示词指南》（https://ark.volcengine.com/region:cn-beijing/docs/82379/2607689?lang=zh），固化于 2026-08-07。
> 本文件只保留写分镜和提示词时**必须遵守**的部分。平台更新后需要人工重新核对。

## 1. 能力与上限（写单元前先数一遍素材）

| 项目 | 官方数值 |
|---|---|
| 单次生成时长 | **单段 30 秒直出** |
| 单次参考素材总量 | 最多 **50 个** |
| 图片 | 最多 **30 张**，4K 分辨率以内 |
| 视频 | 最多 **10 段**，总时长 **≤30s** |
| 音频 | 最多 **10 段**，总时长 **≤30s** |
| 输出格式 | 支持 MOV（延长/编辑任务下音画衔接更好） |
| 宽高比 | 2.5 支持 **[0.4, 2.5]** 之间任意宽高比（2.0 只有 6 档固定） |

**50 个素材的组成是固定的**：`30 张图 + 10 段视频 + 10 段音频 = 50`。

**不是**"40 图 + 5 视频 + 5 音频"——这个常见误解在官方伙伴向导里被明确标为 **INCORRECT**。

**稳定性建议**（超过就会需要抽卡）：

- 主体音视频：**1–5 个主体**效果较好；6–10 个可试但稳定性下降
- 主体音视频时长：**5–10s** 较好，更长会掉稳定性
- 主体图：**1–8 个主体**较好；9–12 可试但下降
- 超过 5 个主体时用**单视图**更稳；需要多视角就拆成多张图分别传，**不要**传一张包含多视角的图
- 多宫格分镜：**≤15 个分镜**为宜，推荐火柴人/线稿，别在图上写太多字
- 视频编辑任务：源视频 **20 秒以内** + **1–5 张**参考图效果较好

**对本技能的含义**：一个生成单元里出现的主体（人物）+ 环境图，尽量控制在 **8 张图以内**，音频 **5–10s**。一集里人物多了，就靠"这个单元只传这一场戏需要的那几个人"来控制，而不是把所有角色图一次全传。

## 2. 第一件要判断的事：有锁定 / 无锁定

Seedance 2.5 会按"素材是否锁定输出属性"把任务分成两类。**产出提示词之前必须先判断**。

| 类别 | 包含任务 | 锁什么 |
|---|---|---|
| **有锁定** | 视频编辑、首帧/首尾帧、视频延长 | 宽高比（严格对齐输入素材）；编辑和延长还会基本锁定时长 |
| **无锁定** | 参考生视频（R2V）、多宫格分镜、关键帧 | 不锁。**宽高比和时长由用户指定** |

**本技能全程走「参考生视频」，属无锁定**，所以：9:16（短剧）或 16:9（电影/动漫）必须**写死在 prompt 里**，不写就没有保障。

顺带一个容易搞混的区别：

- **关键帧参考** → 生成画面**严格对齐**输入图，prompt 第一句必须写"以图片x至图片x的顺序作为关键帧"
- **多宫格分镜参考** → 画面**不严格对齐**，分镜图只提供大致剧情参考，具体动作/运镜/风格要靠 prompt 补齐

## 3. 官方提示词写作公式

把模型当视觉内容生产者，用导演思维写**结构化** prompt：

1. **（R2V）素材指代**：明确每个图/视频/音频按**上传顺序**的编号与**用途**——谁是形象、谁是音色、谁是动作、谁是场景
2. **一句话概述**：主体 + 地点 + 事件 + 题材/风格 + 特殊运镜
3. **具体情节描述**：用**时间戳**或"镜头N"切分，逐段描述画面内容 / 运镜 / 动作 / 台词 / 音效。**尽量正向描述**；反向描述只支持字幕和音频控制
4. **结尾**：补充说明贯穿始终的画面细节——机位 / 运镜 / 环境 / 场景 / 声音 / 氛围

本技能采用的结构化骨架（见 `assets/prompts-template.txt`）：

```
【素材指代】→【一句话概述】→【主体设定】→【环境】→【整体风格】
→【分镜头】(时间轴逐段) →【整体要求】+ 负向控制
```

### 另一个等价的骨架：素材块公式

官方伙伴向导给的是同一件事的另一种切法——**一个必填块 + 四个可选块**：

```
Subject + Action or Event + Scene & Environment + Visual Style + Camera Movement / Cut + Audio
（主体 + 动作/事件）← 唯一必填，其余按需增补
```

每块的推荐句式：

| 块 | 句式 |
|---|---|
| 主体 + 动作 | `<主体> 完成 <主要动作或事件>……` |
| 场景环境 | `……在 <场景与环境> 中。` |
| 视觉风格 | `画面呈现 <视觉风格>。`（光、色板、材质、质感、整体氛围） |
| 运镜 / 切镜 | `使用 <景别、机位、运镜或切镜>。`**要明确点名焦点主体，并把运动和切镜按顺序排好** |
| 音频 | `音频包含 <对白、环境声、音效或音乐>。` |

两种骨架是同一件事，**选一个用，不要混**（见 `references/workflow.md` 的骨架选择）。

### 音频与文本的标记语法

prompt 完全可以用自然语言写。只有当**音乐、音效、对白、字幕这四类需要被明确区分**时，才给每一类套一个标记——**一类一个标记**：

| 标记 | 用途 | 写法 |
|---|---|---|
| `(音乐)` | 场景背后的配乐/底乐 | `(柔和而有节奏的钢琴声在背景中播放)` |
| `<音效>` | 场景内**离散的**声音事件，写清声源与来自哪里 | `<远处传来一声钟响>` |
| `{对白}` | 角色说出的**确切台词**，模型会把括号里的内容念出来 | `林晚轻声用中文说：{你骗了我三年。}` |
| `【字幕】` | 画面上**出现的文字**（标题、字幕、贴字），不说话 | `【第一章：启程】` |

**说台词的语言**：Seedance **默认用中文说话**。写别的语言时，必须在台词前显式声明语言；需要特定地区口音还要额外强化。

> ⚠️ **一个真实的冲突点**：中文区的官方示例用 `【】` 做**结构小标题**（`【主体设定】`、`【分镜头】`），而这份向导用 `【】` 表示**画面上的文字**。两者会撞车。
> **安全做法**：结构小标题继续用 `【】`（中文官方示例就是这么写的，实测可用），但**画面上的文字不要只靠方括号表达**——额外用一句话说清楚，例如"画面中显示一行文字：'一切都可以重新开始'"。这样两种理解都不会出错。

## 4. 参考类多素材映射（最容易翻车的一节）

- 按上传顺序对应编号：**图1 / 图2 / 视频1 / 音频1**，每个素材都要做**文本绑定**
- **不建议只在图片里呈现映射信息**——比如在图上写"张三"、prompt 里写"张三在学校里……"，官方明确说这**容易导致多人混淆或重复角色**
- 多主体要逐一列清映射关系：
  `图1-2是人物1，对应音频1；图3-4是人物2，对应音频2`
- 分工要具体到"参考什么"，部分参考要写明"参考哪一部分"：
  `参考视频1中施法的动作，视频2的环绕式运镜`
- 参考素材本身已经足够精准时，**只做指代、减少画面复述**：
  `严格参考视频1的动作与运镜，顺序与视频保持一致`（不用再逐条写"先抬手、再转身"）

**素材多于 5 个时改用分组写法**（`[角色] [道具] [场景] [运动与音频]` 四组，每组带自己的规则），并遵守**一行一个主体、一行一个参考**。完整规程见 `references/ref-binding.md` 的 3、4 节。

## 5. 时间戳规则（2.5 的核心差异）

- 以 **1 秒**为单位
- **指定时间段内容太少 → 模型自由发挥；内容太多 → 过度剪切或剧情遗漏**。所以分镜表里每一段的文字量要均匀
- **不建议**用时间戳控制频率/频次（比如"一秒摇头3次"）
- 三种合法表达：
  - 明确时间区间——**注意连续性**，要写 `0-3秒……3-7秒……7-15秒`，不要写成 `0-3秒……5-6秒` 这种跳跃表达
  - 时间点控制——`第5s快速向左横移转场`
  - 相对时间控制——`张三呆滞站在原地，3秒后周围人纷纷摇头`

### 时间区间是"预算"，不是"剪辑点"

这一条很关键，容易误解：

- **软边界**：动作落在区间边界前后一点都是正常的，**永远不要指望帧级精确**
- **区间必须连续且不重叠**：它是一个时间预算，不是一个精确的剪辑点
- **每段都要以自己的结束状态收尾**：写 `0-3秒：…… 结束状态：……`
- **既不要把预算留空，也不要超支**：内容太少模型自由发挥，内容太多会切掉或漏掉事件
- **禁止写频率**：永远不要要求"一秒内完成三次动作"这类速率

**什么时候才用精确到秒的时间点**：只在**关键的手递手、进出画、转场、或明确的节拍**上，才用 `第5s` 这种精确时间点。其余情况用区间。

## 6. 负向控制（不写模型就自己加）

### 字幕：先问用户走哪条路线

**字幕归谁做，是完全不同的两条工作流。开工时先确认，不要默认。**

| 路线 | 适用 | 负向控制怎么写 | 分镜表怎么办 |
|---|---|---|---|
| **A. 字幕全部后期添加**（短剧/剧集类最常见） | 有专业剪辑流程，字幕要统一字体、位置、时间轴 | `不生成任何画面文字、字幕或贴字` | 剧本里的 `【字幕：…】`、手机短信、名片地址、屏幕信息，**全部移入「拍摄备注」列**，由后期贴 |
| **B. 让模型生成字幕/文字** | 单条短片、口播、需要画面内文字作为叙事元素 | 只禁对白字幕：`不额外加入对白字幕`，并**显式写出要生成的文字内容** | 文字内容写进 prompt 的对应镜头 |

**走路线 A 时注意**：负向控制要升级成"不生成**任何**画面文字"，而不是只禁对白字幕——否则模型仍可能自己造出标题、UI、水印式的字。同时**画面文字的内容不能在提示词里丢掉**，要完整搬到分镜表的拍摄备注，否则后期不知道贴什么。

**走路线 B 时注意**：官方有 `【字幕】` 标记语法用于画面文字（见本文件第 3 节的音频与文本标记），但中文区官方示例又用 `【】` 做结构小标题——**两者会撞车**。安全的做法是额外用一句话说清："画面中显示一行文字：'……'"。

### 其他负向控制

- 音频可以按维度单独控制：`无bgm，只生成环境音和动作音` / `不要任何声音`
- 编辑类还能精确到时段：`把视频1中4-6秒男人喝咖啡的动作改变为拖地，其余内容不要变化`

## 7. 镜头语言：可以直接写的词

**可以直接写**：基础景别（大全景/全景/中景/近景/特写）、运镜（推/拉/摇/移/跟/环绕/俯冲/后拉/上摇/手持晃动）、机位（低角度/俯视/第一人称）、热门运镜（一镜到底/希区柯克变焦/航拍视角/FPV/子弹时间/手持镜头/回弹变速）。

**必须转译**：过于小众专业的名词，要写成 `[名词 + 描述性解释]`。官方原文的例子：

> "移焦，画面焦点发生平滑转变，原本清晰的前景树木变模糊，背景人物由模糊变清晰"

转场也要写清**触发点与方式**：`第5s快速向左横移转场（向左擦除+自然叠化）`。

**动作与表情**：

- 动作优先**概括性描述**（"连续做了几组高抬腿和空翻"），只在少数记忆点上写具体细节，不重复写相同动作
- 表情写**描述性语句**、少用成语："津津有味地吃饭" → "脸上带着满足的笑容，大口地吃饭"

## 8. 与 Seedance 2.0 的四条差异（决定了为什么这么写）

1. **响应时间戳**：2.0 不响应时间戳、只响应镜头序号；**2.5 响应整数秒时间戳** ← 本技能用时间轴做主骨架的依据
2. **支持多视图**：2.0 不建议用多视图作主体参考，2.5 支持
3. **自由宽高比**：2.0 只有固定 6 档；2.5 支持 [0.4, 2.5] 任意宽高比
4. **提升 V2V 画质**：2.5 输出支持 MOV，在延长/编辑中更好保持颜色亮度与声画一致性

## 9. 失败与修法

| 症状 | 修法 |
|---|---|
| 渲染成一个连续长镜、没有切 | 检查每个镜头有没有独立的时间戳段；确认每镜只给**一个主动作 + 一个运镜** |
| 某个镜头的内容被跳过或压缩 | 减少该单元的镜头数、拉长该段时长、每镜只留一个动作 |
| 切镜点落在动作中途 | 让每一段的句子**结束在动作完成态**，下一段再开启新动作 |
| 单元之间氛围断裂 | 把贯穿整段的效果只声明一次：`全程薄雾，每个镜头` |
| 多人串脸、角色重复 | 检查是不是靠图上写字区分角色；改成文本逐一绑定 |
| 画面里冒出多余字幕 | 补 `不生成任何画面文字、字幕或贴字`（走后期路线时；只写"不要字幕"往往不够） |
| 模型自己加了 BGM | 补 `无bgm，只生成环境音和动作音` |
| 时间轴中间有空洞 | 把区间补成连续：`0-3s / 3-7s / 7-15s` |
